# Writing a unit's spec

Write what will be true of the built repository when this work lands, as
requirement blocks with scenarios, from the work item and the chapters copied
into the place.

Every block names the standing claim it serves, from the claims the item
cites. Work that fits no claim names none; a claim is never invented here.

Do not restate the reasoning. It is in the chapters, and a second copy will
drift from the first.

Do not read the code for the answer. The spec says what the destination
requires; the code is what the next stage changes to meet it.

The work order is everything. Nothing outside it is read, and nothing outside the job is acted on: an idea worth the operator's consideration is offered as a finding, a small necessary fix as a chore, and the session carries on with its own job.
